# Перенос существующих модулей KapibaraV2

Дата: 15 сентября 2026. Источник: соседний проект `KapibaraV2`.
По согласованию перенос отсутствующих модулей отложен.

## WPF.UI и сборка

- Копия `libs/WPF.UI` заменена Git submodule репозитория
  https://github.com/AleksandrFomenko/WPF.UI, commit `5d9d19ba42e5fd283642967dfd836cac611457ea`.
  Ссылки Core и модулей на проекты библиотеки сохранены.
- В прежней копии отсутствовал `source/WPF.UI/Win32/Utilities.cs`, из-за чего библиотека не собиралась.
- Для нового checkout выполнить `git submodule update --init --recursive`.
- Из решения удалена ссылка на отсутствующий `build/Build.csproj`.
- Исправлены конфигурации SheetManager и TestUI: версия Revit теперь соответствует конфигурации решения.
- TestUI использует Revit SDK и совместимую целевую платформу; удалена ссылка на несуществующий проект SheetManager за пределами `source`.
- Исправлены получение идентификатора категории в Core, создание ElementId в LegendPlacer для Revit 2022/2023, ссылка System.Net.Http в ExporterModels и старые обращения к сервисам темы VentilationInstallations.
- URI иконок ленты теперь указывают на сборку Kapibara.RevitToolKit.

Сборка без установки дополнения и запуска Revit:

```powershell
dotnet build Kapibara.RevitToolkit.sln -c Debug.R25 -p:DeployAddin=false -p:LaunchRevit=false
```

## ClashHub

Сопоставлены исходные C# и XAML файлы модуля. Восстановлены кнопки «Выбрать» и «3D» с иконками WPF.UI вместо временных подписей `Edit1`/`Editff`.

Остальные различия относятся преимущественно к nullable-аннотациям, пространствам имён и переходу с SetConfigTheme на ApplyTheme. В новой версии уже присутствуют:

- отслеживание изменений статуса, пересчёт сводки и сохранение XML;
- поиск элементов в текущем документе и связях;
- преобразование bounding box элементов связей и создание 3D вида через ExternalEvent;
- выбор коллизий и отображение их изображений.

Объём функциональности сверялся с локальной старой версией; работоспособность на настоящем отчёте Navisworks внутри Revit требует ручной проверки.

## RiserMate

- Удалены заглушки NotImplementedException в рабочей модели: ExecuteAsync и CreateViewsAsync вызывают сгенерированные ExternalEvent.
- Маркировка активного вида также выполняется через ExternalEvent, как в старой версии.
- Устранена проблема определения категорий фильтра: GetValue возвращает long, который нельзя напрямую передавать Enum.IsDefined для enum с базовым типом int. Использован общий метод Core.
- Enum.GetValues приведён к варианту, доступному в .NET Framework 4.8.

В новой версии уже сохранены детали старого алгоритма: выбор двух нижних труб, обход от верхнего коннектора, остановка на второй трубе, исключение ветки, обработка пересекающихся семейств и вложенных компонентов, скрывающие фильтры 3D видов и маркировка после Regenerate. Выбор параметра сохраняется через PluginConfig вместо отдельного конфигурационного сервиса.

Show3D остаётся заглушкой, которая была и в старой версии. Заглушки дизайн-модели не являются рабочей Revit-моделью.

## Дополнительные найденные потери при переносе

- SortingCategories: восстановлены шаги счётчика `+1` и `+0.1` в последовательной нумерации вложенных семейств и проверка StorageType.Double из старой версии.
- SortingCategories: начальная коллекция категорий передаётся модели; ранее прямое присваивание поля обходило обработчик изменения свойства.
- SolidIntersection: перегрузка с единым значением снова записывает аргумент value, а не индивидуальное значение строки. Восстановлены DynamicResource для цветов темы.
- EngineeringSystems: восстановлены список и начальный выбор правил фильтрации.
- EngineeringSystems и ImportExcelByParameter: PluginConfig зарегистрирован через фабрику с именем каталога и файла. Прежняя регистрация требовала разрешить параметры string через DI и приводила к ошибке открытия окна.

## Ограничения проверки

Итоговая проверка после изменений: решение успешно собрано в Debug.R22–Debug.R27 и Release.R22–Release.R27 (12 конфигураций, 0 ошибок). Installer отдельно собран успешно, без предупреждений. Сборки выполнялись с DeployAddin=false и LaunchRevit=false.

Сборка подтверждает совместимость исходников и XAML; выполнение команд в Revit не проверялось. Остаются предупреждения nullable, устаревших API и MVVM Toolkit.

## SheetManager (бывший ViewManager)

Перенесены сценарии создания и печати из `KapibaraV2/ViewManager/Sheets`, интерфейс переписан на WPF.UI:

- Создание: выбор типа основной надписи, количество, начальный номер, префикс и суффикс, запись в системный и/или пользовательский параметр листа либо рамки. Пакет выполняется одной транзакцией; ошибка записи отменяет создание всего пакета.
- Занятые системные номера получают видимый суффикс `-1`, `-2` и далее вместо невидимых управляющих символов старого модуля.
- Печать: дерево листов по организации диспетчера Revit, выбор вложенных групп, выбор всех и снятие выбора, обновление списка, отдельные PDF или общий PDF с заданным именем. Как и в KapibaraV2, используется встроенный экспорт PDF Revit, а не физический принтер.
- `SheetManagerViewModel` связывает модели обеих страниц, показывает документ и результат операции, обновляет список печати после создания. У страниц заданы DataContext, команды подключены к кнопкам.
- Реализованы StartupCommand, регистрация зависимостей и модальное окно с владельцем Revit; добавлена кнопка Sheet Manager на ленту «Общие». Вызовы API выполняются в контексте внешней команды.
- Третья страница «Нумерация» остаётся неактивной, её реализация отложена по указанию пользователя.

Проверка: SheetManager собран в Debug.R22–Debug.R27 без ошибок и предупреждений; основное дополнение собрано в Debug.R25. Изолированная проверка с тестовой Revit-моделью подтвердила валидацию команд, передачу результата в основную ViewModel, выбор вложенных групп, загрузку и отрисовку обеих страниц без ошибок привязок. Проверка с настоящей RevitAPI вне Revit не запустилась из-за её нативных зависимостей. Создание листов и экспорт PDF в открытом проекте Revit ещё не проверены.

Отложены отсутствующие рабочие модули ChatGPT, ColorsByParameters, FamilyCleaner, HeatingDevices и Insolation, а также вспомогательные и экспериментальные проекты. ViewManager учитывается как SheetManager, а не как отдельный отсутствующий модуль.
